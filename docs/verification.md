## UTC timestamps and relative signal strength (v0.7.2)

The shared receiver supervisor now forces `TZ=UTC0` for all three pipeline children, overriding the HA/host local timezone without requiring tzdata. Regression checks run real subprocesses under inherited Berlin-style POSIX timezone rules, verify UTC in both summer and winter, and compare decoder/gateway timestamps. The actual pinned wmbusmeters binary decrypts the public synthetic fixture in RTL-WMBus input format and preserves UTC reception timestamps and raw signal strength. An isolated real MQTT broker verifies the raw field survives retained state and birth replay, and the eleventh discovery config advertises a unitless diagnostic measurement. All 52 application tests, 32 Proxmox host tests, manifest checks and actual add-on startup/recovery checks passed locally. Destination HA display of the new sensor and corrected future timestamps still needs owner confirmation. Production keys, meter identity, broker and RF captures were not used for these tests.

## Receiver failure diagnostics (v0.7.1)

A destination HA OS VM enumerated the RTL-SDR but its add-on receiver pipeline exited. The original diagnostic filter obscured the cause. Diagnostics now classify known USB failures without relaying upstream text, handle split pipe messages and drain pending stderr before failure cleanup. Tests cover access denial, a busy device, disconnection, exit codes, deduplication and secret suppression. All 50 application tests and 32 Proxmox host tests passed locally. The owner's updated log identified USB interface claiming failure (-5); physically reconnecting the dongle restored reception, and the owner confirmed the add-on works. A stale state from earlier LXC passthrough is plausible but unconfirmed. Version 0.7.2 clarifies the -5 label to cover a missing interface as well as a missing device.

## Runtime demodulator tuning (v0.7.0)

Fast math and algorithm selection now share strict runtime validation across Docker/Compose, native LXC and the Home Assistant add-on. Defaults preserve accurate atan and both demodulation algorithms. Invalid values fail configuration; algorithm choices cannot disable both methods or inject arbitrary flags. Existing add-on options retain defaults. The Proxmox installer exposes Advanced/plain prompts and CLI overrides, and replaces image defaults without duplicating environment keys.

Local checks passed 48 application tests and 32 Proxmox host tests, add-on metadata/version alignment, and actual add-on container startup/recovery with selected flags verified by its synthetic demodulator. All six combinations (accurate/fast math × both/runlength/time2) also started, stayed process-healthy and shut down cleanly with the connected RTL-SDR and the real native binaries. These live smoke checks used a dummy meter identity/key, disabled MQTT and network access, suppressed radio output and retained no RF capture; they verify runtime option handling, not real-key decryption or equal reception quality.

The earlier CPU comparison on a 13th-generation Intel i7-1355U measured about 19.0% of one core at defaults, 11.2% with approximate atan, 15.0% with runlength alone and 8.8% with both optimizations. The demodulator accounted for 17.8 percentage points at baseline, while `rtl_sdr` and the Python supervisor/MQTT worker together used about 1.2. A separate 65-second fan-out of the same live IQ stream recovered the same two distinct CRC-valid telegrams with those four variants; both algorithms produced duplicate copies. No raw IQ, frames or meter identities were saved. Only two distinct telegrams were compared, and time2 alone was not included in that comparison; weak-signal performance and destination-node CPU/reception need local validation.
